# Chinese rules.csv localization workbench

This workbench keeps `data/campaign/rules.csv` as the English source of truth and
stores Chinese translations as individual, reviewable units. It does not edit the
runtime CSV while translating. A localized `rules.csv` is reconstructed only by
the build command, which preserves rule IDs, triggers, conditions, option IDs,
and non-player-facing script syntax.

The two targets are independent:

- `zh-Hans-CN`: mainland Simplified Chinese
- `zh-Hant-TW`: Taiwan-oriented Traditional Chinese

Traditional is translated from English, not converted from Simplified. The two
translations may consult one another for proper-name consistency, but English is
always authoritative.

## Workflow

Run commands from the repository root with Windows PowerShell.

1. Review term decisions in `glossary.csv`. Only rows marked `locked` are
   enforced; `needs-decision` rows must be settled before that term is translated
   widely.
2. Export a small context-aware batch:

       powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\rules_localization.ps1 -Command Export -Locale zh-Hans-CN -BatchSize 12

   The default output is `build/localization/zh-Hans-CN-batch.json`. Use
   `-Offset` to skip untranslated units already assigned elsewhere, or
   `-BatchPath` to choose another output file.
3. Translate the batch according to `translation_brief.md`. Fill `target`, then
   independently fill `backTranslation`. Record ambiguity in `issues`; do not
   silently guess.
4. Import it:

       powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\rules_localization.ps1 -Command Import -Locale zh-Hans-CN -BatchPath .\build\localization\zh-Hans-CN-batch.json

   For an opt-in first draft, the workbench can instead call the authenticated
   DeepL API directly from English. Set `DEEPL_API_KEY` in the process or your
   Windows user environment; the key is never written to the repository. The
   workbench selects DeepL's Free endpoint automatically for keys ending in
   `:fx`.

   The DeepL path protects runtime variables, numbers, and keep-Latin lore names;
   pre-applies locked glossary terms; supplies character and locale instructions;
   converts Chinese quotation marks back to safe ASCII quotes; and can
   back-translate the result for semantic-drift triage:

       powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\rules_localization.ps1 -Command Draft -Locale zh-Hans-CN -BatchSize 100 -BackTranslate

   `Draft` sends the selected source strings to DeepL. It never marks text as
   human-reviewed, and its lexical
   back-translation score is only triage: a fluent reviewer still owns idiom,
   characterization, lore nuance, and final acceptance. Traditional drafts are
   sent from English directly to `ZH-HANT` with Taiwan-Mandarin instructions;
   they are never generated by converting the Simplified store.

   Check the account's live character allowance without exposing the key:

       powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\rules_localization.ps1 -Command Quota

5. Check progress and QA:

       powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\rules_localization.ps1 -Command Report -Locale zh-Hans-CN
       powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\rules_localization.ps1 -Command Check -Locale zh-Hans-CN

6. Once complete, build the localized overlay:

       powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\rules_localization.ps1 -Command Build -Locale zh-Hans-CN

   Output goes to
   `build/localization/<locale>/data/campaign/rules.csv`. The command runs the
   project's required `validate_rules.ps1` against the generated file. A partial
   diagnostic build is possible with `-AllowIncomplete`, but must never ship.

Repeat the process separately for `zh-Hant-TW`.

## Local reference vector index

The workbench maintains a generated sparse-vector database at
`build/localization/reference-index.json`. It indexes each English translation
unit together with its current rule text, option labels, developer notes, and any
current translations. It is roughly 1-2 MB, requires no service or dependency,
and is automatically rebuilt when `rules.csv` or either translation store
changes.

Build it explicitly or search it with an English query:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\rules_localization.ps1 -Command Index
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\rules_localization.ps1 -Command Search -Query "Isaac Leicester personal logs hypershunt" -TopK 5

Search by translation-unit key to inspect the references that unit will receive:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\rules_localization.ps1 -Command Search -UnitKey "shipTrophyIsaCloseIntel::text" -TopK 5

Every exported batch automatically includes four `relatedReferences` per unit
when relevant. Exact/reviewed prior wording receives a small ranking preference,
but the reference records retain their review status. Similarity is a discovery
signal, not translation authority.

This is a deterministic TF-IDF sparse-vector index rather than a neural embedding
model. For this small corpus it is especially effective at finding repeated
commands, lore names, quest terminology, mechanic language, and thematically
linked logs. It is weaker at detecting abstract connections that share no English
vocabulary. The backend can later be replaced by dense embeddings without
changing the batch or translation-store formats.

## Translation-unit model

The exporter creates three kinds of units:

- dialogue/narration from the `text` column;
- only the visible label from each `options` entry (priority and option ID are
  reconstructed from English);
- visible quoted strings used by `SetTooltip`, `SetStoryOption`, and
  `SetTextHighlights` in the `script` column.

Each unit carries neighboring-rule context, rule conditions and notes, protected
runtime tokens, matching glossary entries, a source hash, and review fields. The
importer refuses stale or unknown units.

## Review states

- `draft`: first target-language pass.
- `machine-reviewed`: compared against English using an independent
  back-translation and critique pass.
- `human-reviewed`: checked by a fluent reader.
- `locked`: final wording that should not drift without an explicit decision.

Machine-reviewed is the best available gate when no fluent reviewer is present;
it is not represented as native-speaker approval.

## Artistic Traditional text in the Simplified edition

For a deliberately Traditional inscription, seal, motto, or ceremonial fragment
inside `zh-Hans-CN`, list each exact diegetic fragment in
`traditionalArtFragments` and explain the choice in `artNote`. The checker removes
only those exact fragments before looking for accidental script mixing elsewhere
in the unit.
Never use this exception for ordinary instructions, objectives, tooltips, or
essential gameplay information.

## Safety guarantees

The checker and builder enforce or inspect:

- the exact seven-column CSV schema and valid multiline CSV quoting;
- unchanged rule IDs, triggers, conditions, option priorities, and option IDs;
- preserved `$variables` and format tokens;
- forbidden `U+201C`/`U+201D` smart double quotation marks;
- ASCII double quotation marks for spoken dialogue;
- localized bracketed status lines matching `SetTextHighlights` verbatim;
- stale translations after English source edits;
- stale reference vectors after English or translation-store edits;
- inconsistent translations of repeated English strings;
- locked glossary terms, number drift, English residue, and likely Hans/Hant
  mixing.

Warnings require judgment; errors block a complete build.
